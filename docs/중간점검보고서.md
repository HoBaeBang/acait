# ACAIT 중간 점검 보고서 (Gap Analysis)

**작성일:** 2026-01-20
**대상:** 프론트엔드 팀 & 백엔드 팀

---

## 🚨 긴급 확인 및 조율 필요 사항 (Action Items)

### 1. 알림 시스템 (Notification) - [Gap]
*   **현상**: 프론트엔드에는 알림 관련 UI가 없으나, 백엔드에는 알림 발송 로직(로그 처리)이 존재함.
*   **확인**:
    *   사용자에게 알림 발송 내역을 보여줄 필요가 있는가? (예: "학부모님께 출석 문자가 전송되었습니다")
    *   필요하다면 프론트엔드에 `알림 내역 조회` 페이지 추가 필요.
    *   필요 없다면 백엔드 내부 로직으로만 유지.

### 2. 슈퍼 어드민 (Super Admin) - [Gap]
*   **현상**: 백엔드에는 `ROLE_SUPER_ADMIN`이 존재하지만, 프론트엔드에는 해당 권한을 위한 전용 페이지가 없음.
*   **확인**:
    *   서비스 전체 관리(학원 목록 조회, 강제 폐쇄 등) 기능이 이번 배포 버전에 포함되는가?
    *   포함된다면 프론트엔드에 `/super-admin` 라우트 및 페이지 추가 필요.
    *   아니라면 백엔드 API만 유지하고 프론트엔드 작업은 생략.

### 3. 데이터 초기화 (Seed Data) - [Risk]
*   **현상**: 개발 중 생성된 더미 데이터와 실제 테스트 데이터가 섞여 있음.
*   **제안**:
    *   통합 테스트(Day 12) 시작 전, DB를 초기화하고 **"깨끗한 상태"**에서 시나리오 테스트를 진행할 것을 권장.
    *   백엔드에서 `data.sql` 등을 통해 필수 기초 데이터(테스트용 계정 등)만 남기고 초기화 스크립트 준비 필요.

---

## ✅ 해결된 이슈 (Resolved)

*   **캘린더 데이터 포맷**: `LectureEventDto`에 `id` 필드 누락 문제 -> 백엔드 수정 완료.
*   **수강생 강의 조회**: 학생 기준 수강 목록 조회 API 부재 -> 백엔드 추가 완료.
*   **정산 상세 내역**: 요약 정보만 제공되던 문제 -> 상세 내역 조회 API 추가 완료.

## 📝 결론 및 제언

현재 프로젝트는 **매우 순조롭게 진행**되고 있으며, 프론트엔드와 백엔드 간의 API 스펙 불일치 문제도 즉각적으로 해결되었습니다.

남은 기간 동안은 새로운 기능을 추가하기보다 **"안정성 확보"**에 집중해야 합니다.
특히 **통합 테스트**를 통해 실제 사용 시나리오에서 발생할 수 있는 버그를 찾아내는 것이 최우선 과제입니다.

# ACAIT 고도화 작업 계획 (Advanced Features Roadmap)

**작성일:** 2026-02-01
**목표:** 고객의 심화된 요구사항을 반영하여 정산의 유연성을 확보하고, 학원 운영의 효율성을 높이는 '실장' 역할을 도입한다.

---

## 1. 정산 (Settlement) 고도화

### 1.1 공제 항목 관리 (Deduction Management)
*   **요구사항**: 원장이 학원별로 공제 항목을 자유롭게 추가/관리하고, 각 항목은 '고정 금액' 또는 '비율(%)'로 설정할 수 있어야 한다.
*   **상세 기능**:
    *   **항목 관리**: 원장은 공제 항목명(예: 4대 보험, 식대), 타입(비율/금액), 값(3.3%, 50,000원)을 설정할 수 있다.
    *   **동적 정산**: 정산 실행 시, 설정된 모든 공제 항목을 순차적으로 적용하여 최종 지급액을 계산한다.
*   **개발 방향**:
    *   **Backend**: `DeductionItem` 엔티티 추가, CRUD API 개발, `SettlementService` 로직 수정.
    *   **Frontend**: [공제 항목 관리] UI 개발, 정산 상세 내역에 항목별 공제액 표시.

### 1.2 수강료 이월 (Carry-over)
*   **요구사항**: 학생이 결석 등으로 예정된 횟수를 채우지 못했을 때, 남은 수강료를 다음 달로 넘겨서 정산(차감)해야 한다.
*   **상세 기능**:
    *   **장부(Ledger) 개념 도입**: 학생별로 납부액, 사용액, 이월액을 관리하는 장부 시스템이 필요하다.
    *   **수납 관리**: 학생이 수강료를 납부했을 때 이를 기록하는 기능.
    *   **이월 계산**: (전월 이월금액) + (이번 달 수납액) - (이번 달 수업료) = (다음 달 이월금액).
*   **개발 방향**:
    *   **Backend**: `StudentLedger` 엔티티 및 수납 관리 기능 개발, 정산 로직 전면 재설계.
    *   **Frontend**: [수납 관리] UI 개발, 학생 상세 정보에 [이월 내역] 탭 추가.

## 2. 출결 상태 (Attendance Status) 개선

*   **요구사항**: 결석의 종류를 세분화하고, '휴강' 개념을 추가하여 정교한 출결 관리를 지원한다.
*   **상세 기능**:
    *   **휴강 (Cancelled)**: 수업 자체가 취소된 경우 (정산 X, 보강 X).
    *   **당일 통보 결석 (Absent)**: 학생 사정으로 당일 결석 (정산 O, 보강 X).
    *   **사전 협의 결석 (Req Makeup)**: 미리 연락된 결석 (정산 X, 보강 O).
*   **개발 방향**:
    *   **Backend**: `AttendanceStatus` Enum에 `CANCELLED` 추가.
    *   **Frontend**: `LectureRecordModal` UI 변경 (버튼 분리 및 추가).

## 3. '실장님' 역할 (Manager Role) 추가

### 3.1 역할 배정 및 관리
*   **요구사항**: 강사로 가입한 사용자를 원장이 '실장'으로 역할을 변경할 수 있어야 한다.
*   **상세 기능**:
    *   **역할 변경**: 원장은 [강사 관리] 페이지에서 특정 회원의 역할을 '강사' <-> '실장'으로 변경할 수 있다.
*   **개발 방향**:
    *   **Backend**: `Role` Enum에 `ROLE_MANAGER` 추가, 역할 변경 API 개발.
    *   **Frontend**: [강사 관리] 페이지에 역할 변경 UI 추가.

### 3.2 권한 범위 확장 (운영 업무 수행)
*   **요구사항**: 실장은 단순 조회가 아닌, 학생 관리 및 배정 등 핵심적인 운영 업무를 수행할 수 있어야 한다.
*   **상세 기능**:
    *   **학생 관리**: 신규 학생 등록, 정보 수정, 퇴원 처리 가능.
    *   **강의 배정**: 학생을 특정 강의에 배정하거나 취소 가능.
    *   **전체 조회**: 학원 전체 일정 및 수강료 현황 조회 가능 (수정/삭제 권한은 제한적일 수 있음).
*   **개발 방향**:
    *   **Backend**: `SecurityConfig` 수정하여 `ROLE_MANAGER`에게 학생/배정 관련 API의 쓰기 권한(POST, PUT, DELETE) 부여.
    *   **Frontend**: 실장 로그인 시 관련 메뉴 및 버튼 활성화, 캘린더 기본 뷰 설정.

## 4. 단계별 개발 계획 (Phased Plan)

### 📅 1단계: 기반 마련 (Foundation)
*   **목표**: 출결 상태 개선 및 역할 배정 기능 구현.
*   **주요 작업**:
    *   `AttendanceStatus` Enum 수정 및 UI 반영.
    *   `ROLE_MANAGER` 추가 및 역할 변경 API 개발.

### 📅 2단계: 기능 확장 (Expansion)
*   **목표**: 공제 항목 설정 및 실장님 권한 적용.
*   **주요 작업**:
    *   `DeductionItem` 엔티티 및 관리 UI 개발.
    *   `SettlementService` 로직 고도화.
    *   실장님 권한(학생 관리, 강의 배정) 적용 및 테스트.

### 📅 3단계: 심화 기능 (Advanced)
*   **목표**: 수강료 이월 및 수납 관리 시스템 구축.
*   **주요 작업**:
    *   `StudentLedger` 설계 및 수납 관리 기능 개발.
    *   이월액을 반영한 정산 로직 구현.

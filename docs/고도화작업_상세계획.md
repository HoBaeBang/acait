# ACAIT 고도화 작업 상세 개발 계획

## 1. 개요
본 문서는 ACAIT 시스템의 고도화 요구사항(정산 유연성, 출결 세분화, 실장 역할 도입, 수강료 이월)을 구현하기 위한 상세 개발 계획을 명세한다. 프론트엔드와 백엔드 개발 작업을 단계별로 구분하고, 각 작업에 필요한 기술적 고려사항을 포함한다.

*   **목표**: 고객의 심화 요구사항을 반영하여 시스템의 기능성과 유연성을 극대화한다.
*   **개발 원칙**:
    *   **백엔드 우선**: 데이터 모델 및 API 설계/구현을 선행하여 프론트엔드 개발의 기반을 마련한다.
    *   **점진적 개발**: 복잡도와 의존성을 고려하여 단계를 나누어 개발을 진행한다.
    *   **테스트 주도**: 각 기능 구현 후 단위/통합 테스트를 통해 안정성을 확보한다.

## 2. 단계별 상세 개발 계획

### 2.1 1단계: 기반 마련 (Foundation)

#### 2.1.1 출결 상태 개선 (Attendance Status Improvement)
*   **목표**: 결석 유형 세분화 및 휴강 개념 도입.
*   **영향 범위**: `LectureRecord` (DB), `AttendanceStatus` (Enum), `LectureRecordModal.tsx` (UI)
*   **Backend Tasks**:
    *   **Entity/Enum**: `com.aslan.academymanagement.domain.enums.AttendanceStatus` Enum에 `CANCELLED` (휴강) 추가.
    *   **Service**: `com.aslan.academymanagement.service.record.LectureRecordService` 수정.
        *   `createRecord` 메서드에서 `CANCELLED` 상태가 들어올 경우, 정산 대상에서 제외되도록 로직 확인 및 보완.
        *   `ABSENT` (당일 통보 결석)와 `REQ_MAKEUP` (사전 협의 결석)의 정산/보강 로직이 명확히 구분되는지 재확인.
    *   **API**: 기존 `POST /api/v1/lecture-records` API는 그대로 사용.
*   **Frontend Tasks**:
    *   **UI**: `frontend/src/components/LectureRecordModal.tsx` 수정.
        *   출결 상태 라디오 버튼/셀렉트 박스에 `휴강` 옵션 추가 (value: `CANCELLED`).
        *   기존 `결석` 옵션을 `당일 통보 결석`으로, `보강 필요` 옵션을 `사전 협의 결석`으로 UI 텍스트 변경.
    *   **Validation**: 폼 제출 시 `attendanceStatus` 유효성 검사 업데이트 (필요 시).
*   **Test**: 각 출결 상태별로 수업 기록 후, 캘린더에 반영되는지, 정산 실행 시 해당 상태가 올바르게 처리되는지 확인.

#### 2.1.2 역할 배정 기능 (Role Assignment Feature)
*   **목표**: 원장이 강사의 역할을 '강사' 또는 '실장'으로 변경할 수 있도록 함.
*   **영향 범위**: `Member` (DB), `Role` (Enum), `AdminController`, `AdminService`, `InstructorPage.tsx` (UI)
*   **Backend Tasks**:
    *   **Entity/Enum**: `com.aslan.academymanagement.domain.enums.Role` Enum에 `ROLE_MANAGER` 추가.
    *   **API**: `PUT /api/v1/admin/members/{memberId}/role` 신규 개발.
        *   Request: `com.aslan.academymanagement.dto.MemberRoleUpdateRequest` (memberId, role)
        *   Response: `com.aslan.academymanagement.dto.MemberResponse` (업데이트된 회원 정보)
        *   Auth: `ROLE_OWNER`만 접근 가능하도록 `@PreAuthorize("hasRole('ROLE_OWNER')")` 설정.
    *   **Service**: `com.aslan.academymanagement.service.admin.AdminService`에 `updateMemberRole(memberId, newRole)` 메서드 추가.
        *   `memberId`로 회원 조회, `newRole`로 역할 업데이트 후 저장.
*   **Frontend Tasks**:
    *   **UI**: `frontend/src/pages/admin/InstructorPage.tsx` 수정.
        *   승인된 강사 목록 테이블의 각 강사 옆에 **[역할 변경]** 버튼 또는 드롭다운 추가.
        *   클릭 시 '강사' 또는 '실장'을 선택할 수 있는 모달/팝오버 구현.
    *   **API Integration**: `frontend/src/api/adminApi.ts`에 `updateMemberRole(memberId: number, role: string)` 함수 추가.
    *   **State Management**: 역할 변경 후 `queryClient.invalidateQueries({ queryKey: ['instructors'] })`로 강사 목록 갱신.
*   **Test**: 원장 계정으로 로그인하여 강사 역할을 실장으로 변경 후, DB에 `ROLE_MANAGER`로 저장되는지 확인. 실장 계정으로 로그인하여 권한 변화 확인 (아직 기능은 없지만 Role은 변경되어야 함).

### 2.2 2단계: 기능 확장 (Feature Expansion)

#### 2.2.1 공제 항목 설정 (Deduction Item Configuration)
*   **목표**: 원장이 학원별 공제 항목을 동적으로 설정하고 정산에 반영.
*   **영향 범위**: `DeductionItem` (DB), `SettlementService`, `SettlementPage.tsx` (UI), `AcademySettingsPage.tsx` (신규 UI)
*   **Backend Tasks**:
    *   **Entity**: `com.aslan.academymanagement.domain.DeductionItem` 엔티티 생성.
        *   Fields: `id` (PK), `academy` (ManyToOne, FK), `name` (String, 공제 항목명), `type` (Enum: `PERCENT`, `FIXED_AMOUNT`), `value` (BigDecimal, 비율 또는 금액).
    *   **Repository**: `com.aslan.academymanagement.repository.DeductionItemRepository` 생성.
    *   **API**: `com.aslan.academymanagement.controller.DeductionItemController` 생성.
        *   `GET /api/v1/academies/deductions`: 공제 항목 목록 조회.
        *   `POST /api/v1/academies/deductions`: 공제 항목 추가.
        *   `PUT /api/v1/academies/deductions/{id}`: 공제 항목 수정.
        *   `DELETE /api/v1/academies/deductions/{id}`: 공제 항목 삭제.
        *   Auth: `ROLE_OWNER`만 접근 가능하도록 `@PreAuthorize("hasRole('ROLE_OWNER')")` 설정.
    *   **Service**: `com.aslan.academymanagement.service.DeductionItemService` 생성.
    *   **Service**: `com.aslan.academymanagement.service.settlement.SettlementService` 수정.
        *   `calculateSettlement` 메서드에서 고정 3.3% 대신 `DeductionItemService`를 통해 해당 학원의 `DeductionItem` 목록을 조회.
        *   각 `DeductionItem`의 `type`과 `value`에 따라 강사별 정산 금액에서 순차적으로 차감 로직 구현.
*   **Frontend Tasks**:
    *   **UI**: `frontend/src/pages/AcademySettingsPage.tsx` (신규) 또는 `frontend/src/pages/SettlementPage.tsx`에 **[공제 항목 관리]** 섹션 추가.
        *   테이블 형태로 공제 항목 목록 표시 (항목명, 타입, 값).
        *   항목 추가/수정/삭제 모달/폼 구현.
    *   **API Integration**: `frontend/src/api/settlementApi.ts`에 `deductionItem` 관련 함수 추가.
    *   **Display**: 정산 대시보드/상세 내역에 공제 항목별 상세 내역 표시 (선택 사항, 복잡도 높음).
*   **Test**: 다양한 공제 항목(비율, 고정 금액) 설정 후 정산 실행, 결과 확인.

#### 2.2.2 실장님 권한 적용 (Manager Role Permissions)
*   **목표**: `ROLE_MANAGER`에게 학생 관리 및 강의 배정 권한 부여.
*   **영향 범위**: `SecurityConfig`, `StudentController`, `LectureStudentController`, `StudentFormPage.tsx` (UI), `LectureStudentManagementModal.tsx` (UI)
*   **Backend Tasks**:
    *   **Security**: `com.aslan.academymanagement.config.SecurityConfig` 수정.
        *   `ROLE_MANAGER`에게 다음 API들에 대한 `POST`, `PUT`, `DELETE` 권한 부여.
            *   `StudentController`: `/api/v1/students/**`
            *   `LectureStudentController`: `/api/v1/lecture/{lectureId}/students/**`
    *   **Service**: 각 서비스 메서드에 `@PreAuthorize("hasAnyRole('ROLE_OWNER', 'ROLE_MANAGER')")` 등 권한 어노테이션 추가 (필요 시).
*   **Frontend Tasks**:
    *   **UI**: `frontend/src/App.tsx` 또는 `frontend/src/layouts/MainLayout.tsx`에서 `user.role`에 따라 메뉴 및 버튼 활성화/비활성화 로직 업데이트.
        *   **[학생 등록]**, **[학생 수정]**, **[수강 신청]**, **[수강 취소]** 버튼이 `ROLE_MANAGER`에게도 보이도록.
    *   **Calendar**: `frontend/src/pages/HomePage.tsx`에서 `ROLE_MANAGER` 로그인 시 캘린더 기본 뷰를 '전체 보기'로 설정 (UX 개선).
*   **Test**: 실장 계정으로 로그인하여 학생 등록, 강의 배정, 수정, 삭제가 가능한지 확인.

### 2.3 3단계: 심화 기능 (Advanced Features)

#### 2.3.1 수강료 이월 (Tuition Fee Carry-over)
*   **목표**: 학생별 수강료 납부 및 사용 내역 관리, 이월금 계산 및 정산 반영.
*   **영향 범위**: `TuitionPayment` (DB), `StudentBalance` (DB), `SettlementService`, `StudentFormPage.tsx` (UI), `TuitionPaymentModal.tsx` (신규 UI)
*   **Backend Tasks**:
    *   **Entity**: `com.aslan.academymanagement.domain.TuitionPayment` (수납 내역), `com.aslan.academymanagement.domain.StudentBalance` (월별 잔액/이월금) 엔티티 생성.
        *   `TuitionPayment`: `id`, `student` (ManyToOne, FK), `amount` (BigDecimal), `paymentDate` (LocalDate), `yearMonth` (String), `memo` (String).
        *   `StudentBalance`: `id`, `student` (ManyToOne, FK), `yearMonth` (String), `paidAmount` (BigDecimal), `usedAmount` (BigDecimal), `carryOverAmount` (BigDecimal, 전월 이월), `currentBalance` (BigDecimal, 현재 잔액).
    *   **Repository**: `TuitionPaymentRepository`, `StudentBalanceRepository` 생성.
    *   **API**: `com.aslan.academymanagement.controller.TuitionPaymentController` 생성.
        *   `POST /api/v1/students/{studentId}/payments`: 수강료 납부 기록.
        *   `GET /api/v1/students/{studentId}/balance`: 학생별 월별 잔액/이월 내역 조회.
        *   Auth: `ROLE_OWNER`, `ROLE_MANAGER` 접근 가능.
    *   **Service**: `com.aslan.academymanagement.service.TuitionService` 생성.
    *   **Service**: `com.aslan.academymanagement.service.settlement.SettlementService` 로직 전면 재설계.
        *   `calculateSettlement` 시, `StudentBalance`를 기반으로 강사에게 지급될 금액 계산.
        *   강사 정산은 `usedAmount` (실제 수업 진행 금액)를 기준으로 계산.
        *   월별 `StudentBalance` 업데이트 로직 구현.
*   **Frontend Tasks**:
    *   **UI**: `frontend/src/pages/students/StudentFormPage.tsx` (학생 상세)에 **[수납/이월 내역]** 탭 추가.
        *   월별 납부/사용/이월 금액 표시.
        *   **[수강료 납부]** 모달/폼 구현 (`frontend/src/components/TuitionPaymentModal.tsx` 신규).
    *   **API Integration**: `frontend/src/api/studentApi.ts` 또는 `frontend/src/api/tuitionApi.ts`에 관련 함수 추가.
    *   **Display**: 정산 상세 내역에 이월금 반영 여부 표시 (필요 시).
*   **Test**: 수강료 납부, 수업 진행, 월별 정산 실행 후 이월금 및 강사 정산액 확인.

## 3. 개발 환경 및 협업
*   **Backend**: Spring Boot 3.x, Java 17, JPA/Hibernate, MySQL, Gradle.
*   **Frontend**: React 18, TypeScript, Zustand, React Query, Tailwind CSS, Vite.
*   **Version Control**: Git (Feature Branch Workflow 권장).
*   **Issue Tracking**: 각 기능별 태스크 생성 및 진행 상황 관리.

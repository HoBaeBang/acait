## 3. 핵심 비즈니스 로직 (Logic Specification)

### 3.1 시간표 변경 정책 (Schedule Update Policy)

캘린더에서 일정을 수정할 때, 사용자에게 **"이 일정만 변경"** vs **"앞으로의 모든 일정 변경"**을 선택하게 합니다.

* **Case A: 이번 주만 변경 (Instance Update)**
* **Action:** `schedules`(마스터) 테이블은 건드리지 않음.
* **Logic:** 해당 날짜의 `lecture_records`를 생성(또는 수정)하여 예외 처리를 함.


* **Case B: 앞으로 쭉 변경 (Series Update)**
* **Action:** `schedules` 테이블 자체를 `UPDATE`.
* **Logic:**
1. 기존 `schedules` 데이터 수정.
2. **주의:** 이미 생성된 과거의 `lecture_records`는 수정하지 않음 (데이터 보존).
3. 미래의 날짜에 대해 아직 `lecture_records`가 생성되지 않았다면, 조회 시 변경된 시간표가 적용됨.





### 3.2 보강 관리 시스템 (Makeup Class Logic)

* **결석 처리 시:** 강사가 `결석(ABSENT)` 대신 `보강 필요(REQ_MAKEUP)` 상태를 선택 가능.
* 이때 해당 Record는 정산 금액 **0원** 처리.


* **보강 잡기:** 캘린더 빈 공간에 수업을 생성하고, `Type = 보강(MAKEUP)` 선택.
* **Link:** `보강 필요` 상태인 과거 기록 리스트를 불러와서 선택(Mapping).
* 이 **보강 수업(MAKEUP)**이 완료되면 정산 금액 **1회분** 인정.
* *결과:* 결석(0원) + 보강(1회분) = 총 1회분 정상 과금.



### 3.3 퇴원 및 정산 일할 계산 (Withdrawal)

* **퇴원 처리:** 학생 상태를 `DISCHARGED`로 변경하고 `discharge_date`(예: 1월 15일) 입력.
* **정산 로직:**
* 시스템은 `lecture_records`를 집계할 때, 해당 수업 날짜가 `discharge_date` **이후**라면, 정산 대상에서 **자동 제외**함.
* (이미 생성된 미래 스케줄이 있더라도 과금되지 않음).



### 3.4 정산 및 세금 (Tax Calculation)

* **공식:**
* `세전 총액(Total)` = 
* `공제액(Tax)` = `Total`  0.033 (원단위 절사)
* `실지급액(Real)` = `Total` - `Tax`


* 대시보드와 엑셀 다운로드 시 위 3가지 항목을 모두 표기.

## 4. API 명세서 (API Specification)

### 4.1 [Admin] 테넌트 및 인원 관리

* `POST /api/v1/academies`: 학원 생성.
* `PUT /api/v1/instructors/{id}/approve`: 강사 승인 (Max Member 체크).
* **`PUT /api/v1/admin/academies/{id}/limit` (Super Admin Only):**
* 학원의 `max_members`를 수동으로 상향 조정 (문의 해결용).



### 4.2 [Student] 학생 및 퇴원 관리

* `DELETE /api/v1/students/{id}` -> **API 동작 변경**
* 물리적 삭제가 아닌 `status=DISCHARGED`, `dischargeDate=Today` 업데이트 수행. (기록 보존).



### 4.3 [Schedule] 일정 및 보강

* **`PUT /api/v1/schedules/{id}` (시간표 수정)**
* **Request:** `{ "startTime": "15:00", "scope": "INSTANCE" | "SERIES", "targetDate": "2026-01-14" }`
* **Logic:**
* `INSTANCE`: 해당 `targetDate`의 `lecture_records`만 수정/생성.
* `SERIES`: `schedules` 테이블 업데이트.




* **`POST /api/v1/records` (수업/보강 저장)**
* **Request:** `{ ..., "attendanceStatus": "MAKEUP", "linkedRecordId": 105 }`
* **Logic:** 보강일 경우 `linkedRecordId` 필수. 원본 레코드(`105`)의 상태도 확인.



### 4.4 [Settlement] 정산

* `GET /api/v1/settlements/dashboard`
* **Response:** `{ "totalAmount": 100000, "taxAmount": 3300, "realAmount": 96700 }`

> * [앞으로의 모든 일정 변경] (시간표 자체가 바뀜)
> 
> 



### 5.2 보강 잡기 UX

1. 학생의 출석 상태를 `보강 필요`로 저장.
2. 나중에 캘린더의 빈 시간을 클릭 -> [수업 추가] -> [보강] 탭 선택.
3. **"보강 미배정 학생 리스트"** 드롭다운이 뜨고, 학생 선택 시 자동으로 연결(Link).

### 5.3 정산 대시보드

* 금액 표시 카드에 **"예상 실수령액 (3.3% 공제 후)"** 문구와 금액을 작게 병기하여 혼란 방지.
